# リソースパック仕様 #03: 村人交易画面の全レベル（Lv1〜Lv5）事前解放表示（日本語対応）

本仕様書は `rp_specs/00_RP_ARCHITECTURE.md` の共通規約に基づき、村人との取引画面において現在の取引レベル（見習い等）に関わらず、最初から **全5段階（Lv1 見習い 〜 Lv5 達人）の取引内容・必要エメラルド数・エンチャント詳細** をすべて確認できるようにするJSON UI拡張仕様を定義する。

---

## 1. 機能概要と仕様範囲

* **機能プレフィックス**: `rp03`
* **対象画面ファイル**:
  * `resource_pack/ui/trade_2_screen.json`（クラシックUI設定時：PC・コンソール標準の取引v2画面）
  * `resource_pack/ui/trade_pocket_screen.json`（ポケットUI設定時：スマートフォン・タブレット等のモバイルUI設定画面）
* **実現する体験**:
  * 就職ブロック（書見台・防具鍛冶台・武器鍛冶台・道具鍛冶台・矢細工台など）を置いて村人が就職した瞬間（Lv1 見習い状態）から、取引一覧のスクロールリストに **レベル1〜レベル5までの全取引スロット** を展開表示する。
  * 未解放レベル（Lv2〜Lv5）の取引枠に並んでいる「エンチャントの本」や「エンチャント付き装備」にカーソルを合わせた（またはタップした）際、バニラ標準の日本語ツールチップ（例: `修繕 I`, `効率強化 V`, `耐久力 III` 等）および必要アイテム数がすべて読めるようにする。
* **実績維持（チート非該当）の仕組み**:
  * 統合版クライアントは仕様上、取引画面を開いた時点でサーバーから全5段階分の取引テーブル情報を受け取っている。
  * 本機能はクライアント側のUI非表示マスクとホバー制限を解除して「閲覧可能」にするだけであるため、ビヘイビアーパックを一切必要とせず、実績（Achievements）は100%有効なまま維持される（なお、未解放レベルのアイテムを実際に購入すること自体はサーバー側の判定によりロックされたままとなる）。

---

## 2. アプデ耐性を考慮した JSON UI 差分設計

`rp_specs/00_RP_ARCHITECTURE.md` の規約通り、バニラの `trade_2_screen.json` や `trade_pocket_screen.json` の全文コピーは行わず、該当名前空間（`trade2` / `trade_pocket`）内の対象コントロールのみを最小限の差分としてオーバーライドする。

### 2.1 未解放ティア（Lv2〜Lv5）の非表示マスク解除
バニラの取引画面におけるティア（段階）単位のパネル（`tier_stack_panel` / `trade_tier_panel` 等）では、`bindings` 内の `#tier_visible` が `visible` プロパティにバインドされており、未到達レベルがリスト上から隠されている。

* **変更内容**:
  * ティア単位パネルに対する `#tier_visible` による非表示制御を解除（`"visible": true` 固定、または該当バインディングの除外）し、取引データが存在する全ティア（Lv1〜Lv5）が最初からスクロールリスト上に展開されるようにする。
  * 行商人（ティアが1段しか存在しないエンティティ）の取引画面を開いた際に空欄枠やレイアウト崩れが発生しないよう、各ティア内部の取引アイテム配列（`#collection_length` 等）に応じた動的サイズ計算はバニラ構造を維持する。

### 2.2 エンチャント詳細・アイテムツールチップのホバー閲覧解放（最重要）
バニラではティアを表示させただけでは、未解放段（`#is_tier_unlocked` が `false`、または `#trade_toggle_enabled` が `false` の行）のボタン自体が無効化（`enabled: false`）される影響で、結果アイテム上のホバー判定まで塞がれてエンチャント内容が読めなくなるケースがある。

* **変更内容**:
  * 各取引行（`single_tier_trade` / `trade_item_1` / `trade_item_2` / `output_item` 等）において、取引実行トグル自体がロック中であっても、各アイテムスロット上の詳細確認ホバーコントロール（`hover_button` / `#hover_text` バインディングを持つ要素）は常時有効（`"enabled": true`）に保つ。
  * これにより、未解放のLv2〜Lv5にあるエンチャント本やダイヤ装備にマウスオーバー（またはタッチ選択）した際、バニラ標準のエンチャント名・レベル・アイテム詳細ツールチップが確実にポップアップ表示されるようにする。
  * 未解放段の行をクリックしても購入処理の誤動作やUIフリーズを起こさないよう、「取引選択トグルの有効判定（`#trade_toggle_enabled`）」と「アイテム詳細確認用のホバー領域」が干渉しない階層構造に整理する。

### 2.3 「解放済み（購入可）」と「未解放（プレビュー）」の視覚的区別
最初からLv1〜Lv5がすべて並ぶため、「現在の村人レベルがどこまで上がっていて、どの枠が今すぐ交換できるのか」が一目で判別できるUI表現を維持する。

* **ティア見出しとロック表示の維持**:
  * バニラ標準の日本語ティア見出し（`レベル 1 - 見習い`, `レベル 2 - 徒弟`, `レベル 3 - 一人前`, `レベル 4 - 熟練者`, `レベル 5 - 達人`）を表示したまま維持する。
  * `#is_tier_unlocked` が `false` の未解放ティアには、見出し横の鍵（ロック）アイコン表示やスロット背景の控えめな暗色トーンを残し、「アイテムアイコン・個数・エンチャント文字はくっきり読めるが、未解放プレビュー状態であることが直感的に分かる」デザインとする。
* **日本語ローカライズ対応 (`texts/ja_JP.lang`)**:
  * 独自に補助テキストや見出しラベルを追加する場合は、必ず `texts/ja_JP.lang` に日本語キー（例: `rp03.trade.locked_label=（未解放）`）を定義し、英語表記が画面上に露出しないようにする。

## 3. 受け入れテスト確認項目（Antigravity自己検証リスト）

- [ ] 一度も取引していないLv1の司書・武器鍛冶・防具鍛冶・道具鍛冶・矢細工師に話しかけた際、左側のスクロールリストにレベル1〜レベル5までの全取引枠が最初から表示されること。
- [ ] 未解放レベル（Lv2〜Lv5）に並んでいる「エンチャントの本」や「エンチャント付きダイヤモンド装備」にカーソルを合わせた際、付与されているエンチャント名とレベルが日本語（例: `修繕 I`、`効率強化 V` 等）で正確に表示されること。
- [ ] 現在解放済みのレベル（今すぐ取引可能な枠）と、未解放のレベル（プレビュー表示枠）が鍵アイコンや枠色で明確に見分けられること。
- [ ] 解放済みレベルの通常取引・シフトクリック一括取引・村人のレベルアップ演出がバニラ通り正常に動作すること。
- [ ] 行商人との取引画面を開いた際にもUI崩れや不要な空枠が表示されないこと。
- [ ] ビデオ設定のUIプロファイルが「クラシック」「ポケット」のどちらであっても正常に表示・確認できること。
